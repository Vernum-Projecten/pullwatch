<p class="pw-requirements">Free and open source. macOS 26.6 or later, Apple silicon and Intel. In English, Dutch, German and French.</p>

<Feature
	id="pull-requests"
	kicker="Pull requests"
	title="Every pull request, the moment it opens"
	shot="pull-requests"
	alt="The PRs list in Pullwatch: pull requests from several repositories with their state icon, checks such as 4 of 8 passed, author and age."
	href="/using/pull-requests-and-tags/"
	more="Pull requests and tags"
>
	<p>Pullwatch follows your accounts on github.com, GitHub Enterprise, Azure DevOps, GitLab, Bitbucket, Codeberg, Forgejo and Gitea, and tells you about new pull requests and merge requests as they come in. Each one shows its state and its checks the way GitHub does: passed out of all, a red cross when one failed, amber while they run.</p>
	<p>Everything lands in a history you can search by title, author and repository, together with new tags and releases.</p>
</Feature>

<Feature
	id="menu"
	kicker="Menu bar"
	title="One click from anywhere"
	shot="menu"
	alt="The Pullwatch menu panel with the latest pull requests and their checks, and the latest tags and releases."
	href="/using/menu/"
	more="The menu panel"
	tall
>
	<p>The menu panel shows the newest pull requests and tags with their checks. Click one to open it in the browser, refresh, or open the main window. A dot on the menu bar icon tells you something is unread.</p>
</Feature>

<Feature
	id="repositories"
	kicker="Repositories"
	title="Where each repository stands"
	shot="repo-detail"
	alt="A repository page in Pullwatch: status Problem, the account, the latest tag, and its open, queued, merged and closed pull requests."
	href="/using/repositories/"
	more="Repositories"
>
	<p>Every followed repository gets a page with its open and recent pull requests, the latest tag and the result of its check, worst first in the list. Follow single repositories outside your organizations too, such as a public project you depend on.</p>
</Feature>

<Feature
	id="dependencies"
	kicker="Dependencies"
	title="See what holds an update back"
	shot="dependencies"
	alt="The Dependencies section: packages grouped into can update now, needs a manifest change and blocked, with the repositories that are behind and why."
	href="/using/dependencies/"
	more="Dependencies"
>
	<p>Once a day Pullwatch reads the manifests and lockfiles of your repositories and compares them with the package registries and endoflife.date. It shows which repositories are behind, whether an update fits the current range, and which package blocks it.</p>
</Feature>

<Feature
	id="packages"
	kicker="Packages"
	title="What your repositories publish, and who uses it"
	shot="packages"
	alt="The Packages section: an npm package, a container image and a NuGet package with the repository that publishes each, the latest version, when it was published and how many repositories use it."
	href="/using/packages/"
	more="Packages"
>
	<p>The packages and container images your repositories publish to GitHub Packages, GitLab and Azure Artifacts, one row each, with which of your repositories still use an older version. Your own packages in Dependencies get their latest version from your registry, and their names never go to a public one.</p>
</Feature>

<Feature
	id="security"
	kicker="Security"
	title="Vulnerabilities, with where they come from"
	shot="repo-check"
	alt="The Check tab of a repository: an end-of-life Node version and four advisories for lodash, qs and semver, with the installed version, the fix and how each package got in."
	href="/using/security/"
	more="Security"
>
	<p>Known vulnerabilities come from OSV.dev, with the details of the GitHub Advisory Database: severity, CVSS, CWE and the fixed version. Pullwatch shows whether a package is direct or came in through another one, and adds the repository's own code scanning, secret scanning and Advanced Security alerts.</p>
</Feature>

<Feature
	id="notifications"
	kicker="Notifications"
	title="Notifications that say what happened"
	shot="notifications"
	alt="Pullwatch notifications for a new pull request, a merged pull request, a new release, a new tag and a critical vulnerability."
	href="/using/notifications/"
	more="Notifications"
	tall
	flip
>
	<p>The title says what happened, the subtitle where, and the body who. Turn each kind on or off, mute one repository from the notification itself, and set quiet hours.</p>
</Feature>

<Feature
	id="statistics"
	kicker="Statistics"
	title="How your team ships"
	shot="stats"
	alt="The Statistics section: pull requests opened, drafts, merged and closed, the median lead time, a chart of activity per month and rankings of authors and repositories."
	href="/using/statistics/"
	more="Statistics"
>
	<p>Opened and merged pull requests per week, month or year, the median time to merge, the most active authors and the busiest repositories, from the history Pullwatch already keeps.</p>
</Feature>
