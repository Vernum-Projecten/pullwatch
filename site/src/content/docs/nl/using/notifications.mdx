Elke melding zegt in de titel wat er gebeurde ("Nieuwe pull request", "Pull request gemerged", "Nieuwe release v1.2.0", "Kritieke kwetsbaarheid"), in de ondertitel de repository, en in de tekst de titel met de auteur en co-auteurs ("door mona en 2 anderen"). De profielfoto van een auteur op GitHub komt erbij (één keer opgehaald en een week bewaard); anders toont de melding het icoon van de soort.

## Met en zonder geluid

Nieuwe pull requests, mislukte checks, pull requests die niet meer vanzelf mergen, releases, kwetsbaarheden en beveiligingsmeldingen komen binnen met een banner en een geluid. Tags zonder release, gemergede pull requests, nieuwe versies en nieuwe versies van je eigen packages komen stil binnen, alleen in het Berichtencentrum. De ernstigste kwetsbaarheid staat bovenaan de stapel.

macOS groepeert de meldingen per account en repository. Tot 20 items per poll krijgen elk een eigen melding; daarboven zegt één melding per repository hoeveel het er zijn en noemt de eerste drie.

## Knoppen

- Op een pull request, release of tag: **Markeer als gelezen**, **Repopagina openen** (in Pullwatch) en **Repo dempen**.
- Op een kwetsbaarheid: **Toon in Pullwatch**, **Advies-id kopiëren** en **Repopagina openen**.

**Repo dempen** zet die soort melding uit voor die repository, net als de bel ervan in Instellingen, en het menupaneel biedt **Ongedaan maken** aan tot je het sluit. Klik je op de melding zelf, dan opent de pull request, release of het advies en staat het op gelezen. Lees je een item in Pullwatch, dan verdwijnt de melding ervan uit het Berichtencentrum.

## Instellingen, Meldingen

- Een schakelaar per soort: nieuwe pull requests, gemergede pull requests, releases, tags, kwetsbaarheden, beveiligingsmeldingen en nieuwe versies, elk met een voorbeeld.
- **Mislukte checks van je eigen pull requests** (standaard uit) meldt wanneer de checks van een van je eigen open pull requests mislukken.
- **Pull requests die niet meer vanzelf mergen** (standaard aan) meldt wanneer een open pull request die wachtte om vanzelf te mergen eruit valt: hij ging uit de merge queue (GitHub, Bitbucket Cloud) of de merge train (GitLab), of zijn auto-merge (GitHub, GitLab) of auto-complete (Azure DevOps) ging uit. Een merge queue of merge train krijgt de oranje pijl van Queued; auto-merge en auto-complete, die de lijsten als gewone open pull request tonen, krijgen de pijl in de kleur van open. De titel zegt welke ("Uit de merge queue zonder te mergen"), de ondertitel noemt de pull request (`octo-org/hello-world #44`). Op GitHub zet de tekst er de reden bij die GitHub vastlegde, in de woorden van GitHub ("Reden: …"); de andere diensten geven er geen. Een pull request die gemerged of gesloten is, of weer draft werd, geeft deze melding nooit, en de eerste poll nadat Pullwatch een pull request leert kennen ook niet. De melding volgt de bel van de repository, net als nieuwe pull requests. Agents zien het als `left_queue` in [get_pull_request](/nl/agents/).
- **Nieuwe versies van je eigen packages** (standaard uit) meldt na de dagelijkse check wanneer een package dat een gevolgde repository publiceert een nieuwe nieuwste versie heeft ("Nieuwe versie van greeting", "Versie 1.4.0 gepubliceerd"), stil. Zie [Packages](/nl/using/packages/).
- **Stille uren**: tussen twee tijden komen meldingen zonder geluid binnen, en alleen in het Berichtencentrum. Focus en Niet storen komen nog steeds van macOS.
- Het aantal ongelezen op het Dock-icoon, en een stip op het icoon in de menubalk zolang er iets ongelezen is.

Per repository zet de bel ernaast in Instellingen, Accounts de meldingen uit, terwijl je hem blijft volgen.

Meldingen houden rekening met Focus. Pullwatch gebruikt geen tijdgevoelige meldingen, want die vragen een provisioning profile.
