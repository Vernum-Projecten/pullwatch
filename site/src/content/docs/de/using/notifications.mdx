Jede Mitteilung sagt im Titel, was passiert ist („Neuer Pull Request“, „Pull Request gemergt“, „Neues Release v1.2.0“, „Kritische Sicherheitslücke“), im Untertitel das Repository und im Text den Titel mit Autor und Co-Autoren („von mona und 2 weiteren Personen“). Das Profilbild eines Autors auf GitHub wird angehängt (einmal abgerufen und eine Woche aufbewahrt); sonst zeigt die Mitteilung das Symbol ihrer Art.

## Laut und leise

Neue Pull Requests, fehlgeschlagene Checks, Pull Requests, die nicht mehr von selbst mergen, Releases, Schwachstellen und Sicherheitswarnungen kommen mit Banner und Ton. Tags ohne Release, gemergte Pull Requests, neue Versionen und neue Versionen deiner eigenen Pakete kommen leise an, nur in der Mitteilungszentrale. Die schwerwiegendste Schwachstelle steht oben im Stapel.

macOS gruppiert die Mitteilungen pro Konto und Repository. Bis zu 20 Einträge pro Abfrage bekommen jeweils eine eigene Mitteilung. Darüber sagt eine Mitteilung pro Repository, wie viele es sind, und listet die ersten drei.

## Schaltflächen

- Bei einem Pull Request, Release oder Tag: **Als gelesen markieren**, **Repository-Seite öffnen** (in Pullwatch) und **Repository stummschalten**.
- Bei einer Schwachstelle: **In Pullwatch zeigen**, **Advisory-ID kopieren** und **Repository-Seite öffnen**.

**Repository stummschalten** schaltet diese Art von Mitteilung für dieses Repository aus, genau wie seine Glocke in den Einstellungen, und das Menü bietet **Widerrufen** an, bis du es schließt. Ein Klick auf die Mitteilung selbst öffnet den Pull Request, das Release oder das Advisory und markiert es als gelesen. Liest du einen Eintrag in Pullwatch, verschwindet seine Mitteilung aus der Mitteilungszentrale.

## Einstellungen, Mitteilungen

- Ein Schalter pro Art: neue Pull Requests, gemergte Pull Requests, Releases, Tags, Schwachstellen, Sicherheitswarnungen und neue Versionen, jeweils mit Vorschau.
- **Fehlgeschlagene Checks deiner eigenen Pull Requests** (standardmäßig aus) sagt dir, wenn die Checks eines deiner eigenen offenen Pull Requests fehlschlagen.
- **Pull Requests, die nicht mehr von selbst mergen** (standardmäßig an) sagt dir, wenn ein offener Pull Request, der darauf wartete, von selbst gemergt zu werden, herausfällt: Er hat die Merge Queue (GitHub, Bitbucket Cloud) oder den Merge Train (GitLab) verlassen, oder sein Auto-Merge (GitHub, GitLab) bzw. Auto-Complete (Azure DevOps) wurde ausgeschaltet. Eine Merge Queue oder ein Merge Train bekommt den orangen Pfeil von Queued; Auto-Merge und Auto-Complete, die die Listen als normalen offenen Pull Request zeigen, bekommen den Pfeil in der Farbe von offen. Der Titel sagt, welches ("Merge Queue ohne Merge verlassen"), der Untertitel nennt den Pull Request (`octo-org/hello-world #44`). Auf GitHub fügt der Text den Grund hinzu, den GitHub festgehalten hat, in GitHubs eigenen Worten ("Grund: …"); die anderen Dienste nennen keinen. Ein Pull Request, der gemergt oder geschlossen wurde oder wieder ein Entwurf ist, gibt diese Mitteilung nie, ebenso wenig die erste Abfrage, nachdem Pullwatch einen Pull Request kennenlernt. Sie folgt der Glocke des Repositorys, wie neue Pull Requests. Agents sehen es als `left_queue` in [get_pull_request](/de/agents/).
- **Neue Versionen deiner eigenen Pakete** (standardmäßig aus) sagt dir nach der täglichen Prüfung, leise, wenn ein Paket, das ein Repository veröffentlicht, dem du folgst, eine neue neueste Version hat („Neue Version von greeting“, „Version 1.4.0 veröffentlicht“). Siehe [Pakete](/de/using/packages/).
- **Ruhezeiten**: Zwischen zwei Uhrzeiten kommen Mitteilungen ohne Ton und nur in der Mitteilungszentrale an. Fokus und Nicht stören kommen weiterhin von macOS.
- Die Anzahl ungelesener Einträge im Dock-Symbol und ein Punkt am Symbol in der Menüleiste, solange etwas ungelesen ist.

Pro Repository schaltet die Glocke daneben unter Einstellungen, Konten seine Mitteilungen aus, während du ihm weiter folgst.

Mitteilungen respektieren Fokus. Pullwatch nutzt keine dringlichen Mitteilungen, dafür wäre ein Provisioning-Profil nötig.
