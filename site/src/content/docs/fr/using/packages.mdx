**Paquets** dans la barre latérale (⌘6) liste ce que les dépôts que vous suivez publient dans le registre de leur propre service : paquets npm, NuGet, Maven, RubyGems, PyPI et Composer, images de conteneur, charts Helm et plus encore, depuis GitHub Packages, les registres de paquets et de conteneurs de GitLab, et les flux Azure Artifacts. Pullwatch les lit une fois par jour avec la vérification des versions, et à nouveau avec **Tout vérifier** (⌘R dans cette section). **Dépendances** montre ce qu’un dépôt utilise ; **Paquets** montre ce qu’il publie.

## Une ligne par paquet

Chaque paquet a une seule ligne, regroupée par propriétaire (l’utilisateur, l’organisation ou le groupe, ou pour Azure Artifacts le projet du flux), et non une ligne par version. Les colonnes, chacune triable :

- **Paquet** : le nom, avec le logo de son écosystème (npm, images de conteneur, Docker, NuGet, Maven, RubyGems, PyPI, Helm, Composer, Conan, Go, Terraform, et Rust pour Cargo), ou un symbole pour un paquet générique ou un Universal Package.
- **Dépôt** : le dépôt qui le publie, en entier (`octocat/linguist`). Un paquet qui n’est lié à aucun dépôt, comme un paquet d’un flux Azure Artifacts, affiche son propriétaire en gris.
- **Dernière version** et **Publié** : la version la plus récente et sa date de publication.
- **Utilisé par** : combien des dépôts que vous suivez en dépendent, d’après la vérification des dépendances. Une image de conteneur ou un chart Helm affiche « - » : la vérification ne les reconnaît pas encore comme des dépendances, le nombre est donc inconnu, jamais zéro.

Le champ de recherche trouve un paquet par son nom, par le dépôt qui le publie, ou par un dépôt qui l’utilise. Le menu **Type** de la barre d’outils n’affiche qu’un seul type, comme npm ou **Image de conteneur**.

## L’inspecteur

Sélectionnez un paquet pour voir dans l’inspecteur qui le publie, sa visibilité, le compte et :

- **Versions récentes**, les plus récentes d’abord, chacune avec sa date, le tag dont elle vient (qui ouvre Tags et versions publiées pour ce dépôt), le run ou le pipeline qui l’a publiée, et sa page dans le registre.
- **Utilisé par** : chaque dépôt qui utilise le paquet, avec ses versions : en vert quand il est sur la dernière version, en orange quand il est en retard, et **Seulement par d’autres paquets** quand le paquet n’arrive que par un autre paquet. Cliquez sur un dépôt pour ouvrir sa page.
- **Ouvrir dans le registre** ouvre la page du paquet dans le registre. ⌘O fait la même chose pour le paquet sélectionné.

Pullwatch n’affiche ni nombre de téléchargements ni historique complet : la page du registre les a.

Sur une page de dépôt, l’onglet Aperçu a une ligne **Publie** avec les noms et les dernières versions de ce que ce dépôt publie. Elle ouvre Paquets avec seulement les paquets de ce dépôt, jusqu’à ce que vous choisissiez **Tout afficher**.

## Quand la section est vide

- **Pas encore vérifié** : aucune vérification des versions n’a eu lieu depuis l’arrivée de la section. Choisissez **Tout vérifier**.
- « Non vérifié : la source Registres de paquets de vos comptes est désactivée » : la source est désactivée dans Réglages, **Sources**. **Ouvrir Sources** vous y emmène.
- **Pas d’accès au registre** : aucun de vos comptes ne peut lire son registre de paquets. Chaque compte est listé avec ce qu’il lui faut, et **À propos des autorisations** mène à [Autorisations des jetons](/fr/getting-started/permissions/).
- **Aucun paquet** : les dépôts que vous suivez ne publient rien dans le registre de leur service.

Quand certains comptes peuvent lire leur registre et qu’un autre ne le peut pas, une ligne orange au-dessus du tableau l’indique (« Pas d’accès au registre de paquets de github sur GitHub »), avec la raison dans son infobulle et **À propos des autorisations** à côté.

## Les autorisations à accorder

Pullwatch ne fait que lire. Un compte sans accès l’indique ; le reste de Pullwatch continue de fonctionner.

| Service | Ce qu’il lui faut |
|---|---|
| GitHub, connecté avec GitHub | la GitHub CLI : GitHub ne donne les paquets à aucune GitHub App, Pullwatch les lit donc avec `gh`. Activez **Lire les paquets avec la GitHub CLI** dans l’éditeur de compte (activé tout seul quand `gh` est connecté) et donnez la portée à `gh` avec `gh auth refresh -h github.com -s read:packages` |
| GitHub, avec `gh` ou un jeton classique | la portée `read:packages` (`gh auth refresh -s read:packages`) |
| GitLab | `read_api`, dont Pullwatch a déjà besoin |
| Azure DevOps, avec un jeton | Packaging (Read) |
| Azure DevOps, avec `az` | le rôle Feed Reader sur le flux, ou un jeton avec Packaging (Read) |

Bitbucket, Codeberg, Forgejo et Gitea ne sont pas lus pour les paquets. Voir [Autorisations des jetons](/fr/getting-started/permissions/) pour toutes les portées.

## Une notification pour une nouvelle version

Réglages, Notifications, **Nouvelles versions de vos propres paquets** vous prévient quand un paquet publié par un dépôt suivi a une nouvelle dernière version : « Nouvelle version de greeting », avec le dépôt et « Version 1.4.0 publiée ». Elle est désactivée par défaut. Elle arrive après la vérification quotidienne, une par paquet dont la dernière version a changé depuis la vérification précédente, en silence, uniquement dans le Centre de notifications. Une première vérification et un nouveau paquet ne déclenchent rien. Cliquer dessus ouvre Paquets, avec une recherche sur ce paquet.

## Dépendances internes

Quand un dépôt que vous suivez dépend d’un paquet qu’un autre dépôt suivi publie, la vérification des dépendances prend sa dernière version dans votre propre registre au lieu du registre public, et le paquet indique **Interne**. Voir [Paquets internes](/fr/using/dependencies/#paquets-internes).
