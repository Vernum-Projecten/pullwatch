Chaque notification dit ce qui s’est passé dans le titre (« Nouvelle pull request », « Pull request fusionnée », « Nouvelle version v1.2.0 », « Vulnérabilité critique »), le dépôt dans le sous-titre, et le titre avec son auteur et ses coauteurs (« par mona et 2 autres personnes ») dans le corps. La photo d’un auteur GitHub est jointe (récupérée une fois et conservée une semaine) ; sinon, la notification affiche l’icône de son type.

## Avec ou sans son

Les nouvelles pull requests, les échecs de checks, les pull requests qui ne fusionnent plus d’elles-mêmes, les versions publiées, les vulnérabilités et les alertes de sécurité arrivent avec une bannière et un son. Les tags sans version publiée, les pull requests fusionnées, les nouvelles versions et les nouvelles versions de vos propres paquets arrivent en silence, uniquement dans le Centre de notifications. La vulnérabilité la plus grave passe en tête de la pile.

macOS regroupe les notifications par compte et par dépôt. Jusqu’à 20 éléments par interrogation, chacun reçoit sa propre notification ; au-delà, une notification par dépôt indique leur nombre et liste les trois premiers.

## Boutons

- Sur une pull request, une version publiée ou un tag : **Marquer comme lu**, **Ouvrir la page du dépôt** (dans Pullwatch) et **Mettre le dépôt en sourdine**.
- Sur une vulnérabilité : **Afficher dans Pullwatch**, **Copier l’identifiant de l’avis** et **Ouvrir la page du dépôt**.

**Mettre le dépôt en sourdine** désactive ce type de notification pour ce dépôt, comme sa cloche dans les Réglages, et le panneau du menu propose **Annuler** jusqu’à ce que vous le fermiez. Cliquer sur la notification elle-même ouvre la pull request, la version publiée ou l’avis et le marque comme lu. Lire un élément dans Pullwatch retire sa notification du Centre de notifications.

## Réglages, Notifications

- Un interrupteur par type : nouvelles pull requests, pull requests fusionnées, versions publiées, tags, vulnérabilités, alertes de sécurité et nouvelles versions, chacun avec un aperçu.
- **Échec des checks de vos propres pull requests** (désactivé par défaut) vous prévient quand les checks d’une de vos pull requests ouvertes échouent.
- **Pull requests qui ne fusionnent plus d’elles-mêmes** (activé par défaut) vous prévient quand une pull request ouverte qui attendait d’être fusionnée automatiquement en sort : elle a quitté la merge queue (GitHub, Bitbucket Cloud) ou le merge train (GitLab), ou son auto-merge (GitHub, GitLab) ou son auto-complete (Azure DevOps) a été désactivé. Une merge queue ou un merge train reçoit la flèche orange de Queued ; l’auto-merge et l’auto-complete, que les listes montrent comme une pull request ouverte ordinaire, reçoivent la flèche dans la couleur d’ouverte. Le titre dit lequel (« Sortie de la merge queue sans fusion »), le sous-titre nomme la pull request (`octo-org/hello-world #44`). Sur GitHub, le texte ajoute la raison notée par GitHub, dans ses propres mots (« Raison : … ») ; les autres services n’en donnent pas. Une pull request fusionnée, fermée ou repassée en brouillon ne donne jamais cette notification, pas plus que la première interrogation après que Pullwatch découvre une pull request. Elle suit la cloche du dépôt, comme les nouvelles pull requests. Les agents la voient comme `left_queue` dans [get_pull_request](/fr/agents/).
- **Nouvelles versions de vos propres paquets** (désactivé par défaut) vous prévient, après la vérification quotidienne, quand un paquet publié par un dépôt suivi a une nouvelle dernière version (« Nouvelle version de greeting », « Version 1.4.0 publiée »), en silence. Voir [Paquets](/fr/using/packages/).
- **Heures calmes** : entre deux heures, les notifications arrivent sans son et uniquement dans le Centre de notifications. Les modes Concentration et Ne pas déranger restent gérés par macOS.
- Le nombre de non-lus sur l’icône du Dock, et un point sur l’icône de la barre des menus tant qu’il reste quelque chose de non lu.

Pour chaque dépôt, la cloche à côté de lui dans Réglages, Comptes désactive ses notifications tout en continuant à le suivre.

Les notifications respectent le mode Concentration. Pullwatch n’utilise pas les notifications urgentes, qui demanderaient un profil de provisionnement.
