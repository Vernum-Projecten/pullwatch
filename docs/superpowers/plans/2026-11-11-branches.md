# Branches Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Een sectie Branches in het hoofdvenster die per gevolgde repo laat zien welke branches bewegen, wie er commit en wanneer, met doorklikken naar de vergelijking in de browser.

**Architecture:** Zoals tags: elke provider geeft per repo de branches met hun laatste commit (`PRProvider.branches(in:unchanged:)`), `PollEngine` onthoudt de heads in `SeenState` en maakt bij een verandering een `BranchPush`. Pushes staan in een eigen bestand `branches.json` (`BranchLog`), los van `history.json`, zodat ze nooit meetellen voor ongelezen, de Dock-badge, het menu of de MCP-tools. Het app-model `BranchesModel` houdt de log bij en `BranchesView` toont hem.

**Tech Stack:** Swift 6, SwiftUI (macOS 26.6), Swift Testing, `PullwatchKit`.

**Spec:** `docs/superpowers/specs/2026-11-11-branches-design.md`

## Global Constraints

- macOS 26.6, universal; geen deployment target per target.
- Elke tekst voor de gebruiker in nl, en, de en fr; na een tekstwijziging `bash scripts/dev/sync-strings.sh` en de vertalingen invullen (`LocalizationTests`).
- Geen em dashes, geen "·" als scheidingsteken, geen "niet X maar Y" in UI, docs en commits.
- Commentaar in het Nederlands, Xcode-inspringing (4 spaties).
- Alleen wat een andere module of de app gebruikt is `public`; wat alleen de package-modules delen `package`.
- Geen meldingen voor pushes; pushes nooit in `History`, `NotificationPlanner`, het menu of de MCP-tools.
- Een fout bij branches, ook `.rateLimited`, laat de PR's en tags van dezelfde poll ongemoeid.
- Branches volgen met PR's mee: `WatchSet.branches` krijgt bij decoderen zonder sleutel de waarde van `prs`; `NewRepoDefault.prs` en `.prsAndTags` geven `branches: true`.
- Seed-venster: 14 dagen (`PollEngine.branchSeedWindow = 14 * 86_400`).
- Bewaren: zo lang als `HistoryRetention`.
- Gates voor elke commit: zie `CLAUDE.md` (Gates). Op deze Mac `-only-testing:PullwatchTests` en `build-for-testing` in plaats van de UI-tests.
- Werk blijft lokaal op `feat/branches`: geen push, geen PR, tot Alessandro de sectie in de app heeft gezien.
- Commits: conventionele onderwerpen in het Engels, geen AI-attributie.

## Review Focus

1. Een repo met meer dan 100 branches: alle branches moeten meetellen (paginering), anders lijkt een branch na de grens "nieuw" of "verwijderd". Test in Task 5 (GitHub, `pageInfo`) en per provider de paginering.
2. Branchnamen met `/`, `#`, spaties of niet-ASCII in de vergelijkings-URL: correct gecodeerd, de link opent de juiste branch. Test per provider op `compareURL`.
3. Een repo die tijdelijk onbereikbaar is (404, geen toegang) en terugkomt: geen stroom "nieuwe branch"-rijen; de onthouden heads blijven staan zolang de repo onbereikbaar is. Test in Task 4.
4. Branches voor een repo uit en weer aan: opnieuw stil seeden binnen 14 dagen, geen rij per bestaande branch als push. Test in Task 4.
5. Een seed-branch zonder commitdatum of met een datum in de toekomst: geen seed-rij zonder datum, een toekomstige datum telt als nu. Test in Task 4.

  public struct BranchPush: Codable, Hashable, Identifiable, Sendable {

  public struct BranchLog: Codable, Equatable, Sendable {
      public private(set) var pushes: [BranchPush]   // nieuwste eerst (pushedAt)

      public mutating func removeAccount(_ id: UUID)

  - `Fetched.branches: BranchOutcome?` (nil: niet aan de beurt), met
    `struct BranchOutcome: Sendable { var repos: [String]; var fetch: BranchFetch?; var comparisons: [String: BranchComparison]; var error: ProviderError? }` (sleutel comparisons: `"{repo.lowercased()}:{branch}"`).
  - `static func fetchBranches(_ provider: any PRProvider, _ repos: BranchRepos) async -> BranchOutcome` gooit nooit; `listRepos()` alleen als `followsBranchesByDefault`, en dan hergebruikt uit de tag-fetch van dezelfde poll als die er al was.
  - `func handleBranches(_ account: Account, _ outcome: BranchOutcome, userId: String, provider: any PRProvider, at t: Date) -> [BranchPush]` (in de actor).
  - `PollResult.branchPushes: [BranchPush]` (public, nieuwste eerst).
  - `static func isOwn(_ head: BranchHead, userId: String, account: Account) -> Bool`: `authorId` gelijk aan `userId` (hoofdletterongevoelig), of `authorEmail` gelijk aan `account.email`, of `authorId`/`authorName` gelijk aan `account.login`.

Werking van `handleBranches`, per repo die niet onbereikbaar is:
1. Niet bekend (geen `BranchHeads`): seed. Elke head met `committedAt` binnen `t - branchSeedWindow ... t` wordt een `.recent`-rij met `pushedAt = min(committedAt, t)`; heads zonder datum worden alleen onthouden.
2. Bekend en in `unchangedRepos`: alleen `seenAt = t`.
3. Bekend en veranderd: per head met een andere sha: `comparisons` geeft `behind > 0` → `.forcePush` (`commits: nil`), anders `.push` met `commits: ahead` (of nil zonder vergelijking). Een head die niet bekend was → `.newBranch` (`commits: nil`, `oldSha: nil`). Een verdwenen branch geeft niets.
4. Heads, vingerafdruk en `seenAt` bijwerken.
Een repo die niet meer gevolgd wordt: zijn `BranchHeads` vergeten (opnieuw aanzetten seedt). Een onbereikbare repo: `BranchHeads` blijft staan, geen rijen. Bij `outcome.error`: niets veranderen; bij `.rateLimited(until:)` `branchesRateLimitedUntil = until` en geen branch-fetch tot dan. `webURL` = `provider.compareURL(in:from:to:)` met de oude en nieuwe sha, anders `head.webURL`.

`fetchBranches` vraagt de vergelijkingen op voor de veranderde heads (oud bekend, nieuw anders), hooguit `branchCompareLimit`, nieuwste `committedAt` eerst; een fout bij één vergelijking laat die weg.
